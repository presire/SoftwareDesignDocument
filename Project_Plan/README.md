# Project_Plan — プロジェクト計画書の項目説明

本ディレクトリのプロジェクト計画書 2 冊について、書類を構成する各項目 (前付け・章・節) の内容を簡単に説明する。  

| ファイル | 位置づけ | 枚数 |
|---|---|---|
| `[プロジェクト計画書]コンペ提出版_経費精算業務改革プロジェクト.pptx` | コンペ・提案提出用。記載例の項目に提案向けの節を追加した完全版 | 85 |
| `[プロジェクト計画書]記載例_経費精算業務改革プロジェクト.pptx` | 計画書の標準的な記載例。必須節と主要な任意節のみ | 46 |

- どちらも架空の「経費精算業務改革プロジェクト」を題材にした例であり、内容を他案件へ流用しない。
- 下表の「コンペ」「記載例」列は、その項目を収録しているか (○) を示す。「区分」は計画書として必須か任意かを示す。

## 書類の構成

```
表紙 → 目次 → 更新履歴
→ 1 方針 → 2 スケジュール → 3 体制 → 4 コミュニケーション計画
→ 5 プロジェクト管理計画 → 6 プロジェクトルール → 7 その他
→ クロージング (コンペ提出版のみ)
```

各章の先頭には、章番号・章タイトル・章内の節一覧を示す**章扉**が入る。  
本文の各スライドは、上部に結論を1文で示す**リード文**を置き、その下に表・箇条書き・カード・図などで詳細を示す。  

## 前付け・後付け

| 項目 | 説明 | コンペ | 記載例 |
|---|---|:-:|:-:|
| 表紙 | 文書名・プロジェクト名・提出先 (御中)・作成組織・作成日・版・機密区分。<br>コンペ版はキーメッセージと主要KPI (リードタイム・工数削減・稼働日) も載せる | ○ | ○ |
| 目次 | 章・節の一覧と掲載ページ | ○ | ○ |
| 更新履歴 | 版ごとの変更記録 (No. / 日付 / 更新者 / 版 / 主な変更点 / 備考) | ○ | ○ |
| クロージング | 提案の締めくくり。<br>謝辞と提案責任者の連絡先 | ○ | - |

## 1 方針

プロジェクトを「なぜ・何を・どこまで・どう」行うかを定める章。  

| 節 | 説明 | 区分 | コンペ | 記載例 |
|---|---|---|:-:|:-:|
| エグゼクティブサマリー | 提案全体の要点 (目標・手段・効果) を 1 枚に要約する | 任意 | ○ | - |
| 現状認識と課題 | 現状の業務の問題点とその原因を整理する | 任意 | ○ | - |
| 背景と目的 | プロジェクトを行う理由と目的。以降の全判断の拠り所 | 必須 | ○ | ○ |
| 本提案の特長 | 提案の強み・差別化ポイントを示す | 任意 | ○ | - |
| 実施方針 | 進め方・優先順位・品質に対する基本姿勢 | 必須 | ○ | ○ |
| 全体像 | 現状 (As-Is) と目指す姿 (To-Be) を並べ、対象を 1 枚で俯瞰する | 任意 | ○ | ○ |
| To-Be 業務フロー | 改革後の業務の流れ (申請〜承認〜支払) を示す | 任意 | ○ | - |
| 対象の概要 | 対象となる業務・システム・組織・利用者と規模の一覧 | 必須 | ○ | ○ |
| システム連携構成 | 導入するシステムと周辺システム (会計・人事等) との連携関係 | 任意 | ○ | - |
| スコープ (対象・対象外) | 作業の範囲と範囲外を明示し、後からの拡大解釈を防ぐ | 必須 | ○ | ○ |
| 目標と成功基準 | 完了の判定条件と稼働後 KPI、その測定方法・時期 | 必須 | ○ | ○ |
| 導入効果 (定量・定性) | 工数削減などの定量効果、定性効果と試算の前提 | 任意 | ○ | - |
| 法令・制度対応方針 | 関係する法令・制度 (電子帳簿保存法・インボイス制度・個人情報保護) への対応方法 | 任意 | ○ | - |
| 前提条件・制約条件 | 計画が成り立つ前提と守るべき制約、前提が崩れた場合の対応 | 必須 | ○ | ○ |
| 要求・要件の定義方針 | 要求の集め方・粒度・確定までの手順 | 任意 | ○ | ○ |
| 要求の優先順位付け | 全てを実現できない場合の取捨選択ルール (MoSCoW 分類) | 任意 | ○ | - |

## 2 スケジュール

| 全体スケジュール | 全期間の工程をガントチャートで示す (共同・実施側・オーナー側作業を色分け) | 必須 | ○ | ○ |
| マイルストーンと完了基準 | 各節目の日付・完了基準・判定者 | 必須 | ○ | ○ |
| 検証・テスト計画 | 検証の種類ごとの目的・実施者・環境・時期・合格基準 | 任意 | ○ | - |
| フェーズ別スケジュール | 主要フェーズを週単位などで詳細化したガントチャート | 任意 | ○ | ○ |
| 移行・切替計画 | 新しい業務・システムへの移行手順と切替時のリスク対策 | 任意 | ○ | - |
| 研修・定着化計画 | 利用者向け研修と稼働後の定着化支援、定着の目標値 | 任意 | ○ | - |

## 3 体制

| 節 | 説明 | 区分 | コンペ | 記載例 |
|---|---|---|:-:|:-:|
| オーナー側体制 | 依頼元 (発注者) 側の意思決定層と実行チームの体制図 | 必須 | ○ | ○ |
| 実施側体制 | 実行する側 (受託者) の体制図と役割分担 | 必須 | ○ | ○ |
| 主要メンバー | 双方の主要メンバー、要員配置と稼働率 | 任意 | ○ | - |

| ステークホルダー | 関係者ごとの関心・関与度と対応方針 | 任意 | ○ | ○ |

## 5 プロジェクト管理計画

課題・リスク・変更・品質・進捗・費用・文書・セキュリティの管理方法を定める章。  

| 節 | 説明 | 区分 | コンペ | 記載例 |
|---|---|---|:-:|:-:|
| 課題関連図 | Q&A・課題・議事録の関係と情報の流れを 1 枚で示す | 任意 | ○ | ○ |
| Q&A 管理 | オーナー側への確認事項の起票・回答期限・共有方法 | 任意 | ○ | ○ |
| 課題管理 | 顕在化した問題の登録から解決までの流れと台帳管理 | 必須 | ○ | ○ |
| リスク管理 | リスク登録簿、評価基準 (発生可能性・影響度)、対応方針と見直し頻度 | 必須 | ○ | ○ |
| 変更管理 | スコープ・日程・予算の変更手順 (影響分析 → 変更管理委員会 (CCB) の承認 → 反映) と承認権限 | 必須 | ○ | ○ |
| 品質管理 | フェーズごとの品質目標・指標と、品質保証の体制・プロセス | 必須 | ○ | ○ |
| 進捗管理 | 進捗の測定指標 (SPI・CPI 等) と、閾値を超えた場合の是正 | 必須 | ○ | ○ |
| 予算・コスト管理 | 予算の内訳と執行管理、予実差異の報告基準 | 任意 | ○ | ○ |
| 調達・外部委託管理 | 外部調達・再委託の対象・契約形態・管理方法 | 任意 | ○ | - |
| ドキュメント・構成管理 | 成果物の保管場所 (フォルダ構成)・版管理・ベースライン | 必須 | ○ | ○ |
| 情報セキュリティ管理 | 情報の取扱区分、アクセス統制、インシデント時の対応、個人情報の扱い | 必須 | ○ | ○ |
