# 開発委託仕様書 見本の項目説明

本ディレクトリの開発委託仕様書見本 (MochDatの例) について、各シートの記載項目を簡単に説明する。  
本書は開発委託の仕様書と提案依頼書 (RFP) を兼ねる。  

## 対象ファイル

| ファイル | 対象 | ライブラリ形式 |
|---|---|---|
| `[開発委託仕様書]MochDat_Linux(.so).xlsx` | Linux | 共有ライブラリ |
| `[開発委託仕様書]MochDat_Windows(.dll).xlsx` | Windows | ダイナミックリンクライブラリ |

2ファイルは同じシート構成であり、OS固有の記述 (黄色背景・◆) だけが異なる。  
シート4とシート6はシート全体がOS固有である。  

## 全シート共通のヘッダ

| 項目 | 説明 |
|---|---|
| システム名 / ライブラリ名 | 対象システムと対象ライブラリ |
| 作成者 / 作成日 / 更新者 / 更新日 | 作成と最終更新の担当者・日付 |
| シート見出し | シートの題名 |

## 0.表紙

| 項目 | 説明 |
|---|---|
| 表題 / 副題 | 文書名と、対象OS・ライブラリ形式 |
| 文書情報 | 文書番号、文書版数、発行日、機密区分、文書名、発注者、発注者窓口、委託対象、<br>対象プラットフォーム、成果バイナリ、本書の位置付け、別紙、関連文書 |
| 提出期限・問合せ先 | 質問受付締切、提案書・見積書提出期限、問合せ先 |
| 本書の取扱い | 秘密情報としての扱い、辞退・非選定時の返却や消去、改訂時の扱い |
| 凡例 | 黄色背景、橙色のシート見出し、◆、要件区分 (必須 / 推奨 / 任意) 、<br>納品物ID (DLV-xx) 、役割分担表の記号 (◎ / ○ / △ / −) の意味 |

## 0-1.改版履歴

| 項目 | 説明 |
|---|---|
| 版 | 文書の版数 |
| 改版日 | 改版した日付 |
| 区分 | 新規・変更・発行などの別 |
| 改版箇所 (シート) | 変更したシート |
| 改版内容 | 変更の要旨 |
| 変更者 | 改版した人 |

## 0-2.シート構成

| 項目 | 説明 |
|---|---|
| シート一覧 | 各シートの名称、記載内容、OS差分 |
| シート間の関係図 | 文書管理・依頼内容・要件・進め方・提案依頼の各グループに属するシート |
| 主な相互参照 | シート間で値を一致させる項目 (工程・日程、納品物ID、数値基準、新規API、要件ID、支給品) |

## 1.依頼概要

| 項目 | 説明 |
|---|---|
| 背景・目的 | 開発を委託する背景と目的 |
| 委託概要 | 案件名、文書番号、対象ライブラリ、対象版、委託範囲、契約形態、期間、納品日程、検収日、発注者・窓口 |
| 全体構成図 | 利用側・ライブラリ・OSの関係と対象プラットフォーム |
| 前提条件・制約 | 互換性の維持、外部設計で確定する事項、署名の分担、基準ビルド環境など |
| 支給品 | 発注者が提供する資料・データの内容、提供時期、返却・消去の扱い |

## 2.委託範囲・役割分担

| 項目 | 説明 |
|---|---|
| 工程別役割分担 | 工程ごとの契約形態、期間、発注者と受託者の役割 (◎ / ○ / △ / −) 、主な成果物 |
| 委託範囲と対象外 | 受託者に委託する作業と、委託しない作業 |
| 作業項目 (WBS) | 作業項目、対応工程、成果物、備考 |
| 発注者が行う作業 | 受入テスト、署名・配布、リリース判定など発注者側の作業 |

## 3.機能要件

| 項目 | 説明 |
|---|---|
| 機能要件一覧 | 要件ID (FR-xxx) 、区分 (必須 / 推奨 / 任意) 、要件、確認方法、備考 |
| 新規API一覧 | 追加するAPI、関数、概要、版管理 |
| 排他制御・中断要求 | 新規機能に求める排他制御と中断の仕様 |
| 新規APIプロトタイプ (案) | 関数宣言の案 |
| 構造体配置 | 新規構造体のオフセット、サイズ、フィールド、型、説明 |
| 既知不具合 (修正対象) | 管理番号、現象、修正方針 |
| 外部設計で確定する事項 | 本書では確定せず外部設計で決める事項 |

## 4.インタフェース・ABI要件

| 項目 | 説明 |
|---|---|
| 本シートの位置付け | 対象バイナリとABI互換性を保証する範囲 |
| 対象バイナリの特定 | 成果バイナリ、シンボリックリンク (.so) またはインポートライブラリ (.dll) 、バージョン、比較基準 |
| 公開ABI要件 | 要件ID (IF-xxx) 、区分、要件、確認方法、備考 |
| エクスポート定義の例示 | .soはバージョンスクリプト、.dllはモジュール定義ファイル (.def) の新規分 |
| 構造体配置の規則 | 構造体のレイアウトに関する要件 |
| ABI互換性の合否 | 旧版との比較方法と合格条件、許容する依存ライブラリ、シンボル版の上限など |

## 5.非機能要件

各項目は要件ID (NFR-xxx) 、区分、要件、確認方法、備考の表で記載する。  

| 項目 | 説明 |
|---|---|
| 性能 | 基準データ・基準機と処理時間の目標 |
| 資源 | メモリなど消費資源の上限 |
| 信頼性 | 不正入力に対してクラッシュ・ハングしないこと |
| スレッド安全性 | 同時呼出し時の排他制御 |
| 移植性 | 対象OS・アーキテクチャでの動作 |
| 保守性 | 警告0件や静的解析の通過 |
| 互換性 | 旧版向けの利用側が再構築なしで動作すること |
| 診断 | 失敗の原因をエラーコードで区別できること |

## 6.開発環境・ビルド要件

| 項目 | 説明 |
|---|---|
| 本シートの位置付け | 基準構築環境と再現性の要求 |
| ビルドツールのバージョン指定 | OS、コンパイラ、ビルドツール、CIの指定 |
| 環境要件 | 要件ID (ENV-xxx) 、区分、要件、確認方法、備考 |
| コンパイル・リンクオプションの例示 | 指定するコンパイル・リンクオプション |
| バージョン管理の運用 | ソース管理・ビルド定義の納品に関する要件 |

## 7.品質・テスト要件

| 項目 | 説明 |
|---|---|
| 適用範囲と方針 | 品質目標の位置付けと、納品時の未解決不具合の扱い |
| テスト工程 | 工程、実施者、環境、合格基準、証跡 |
| 品質要件 | 要件ID (QA-xxx)、区分、要件、確認方法、備考 |
| 不具合重大度と取扱い | 重大度A〜Dの定義、例、納品時の扱い |
| レビュー | マイルストーンごとのレビューと指摘のクローズ |
| 測定・検査ツール | 用途ごとのツール (Linux版 / Windows版) と証跡 |

## 8.セキュリティ・OSS要件

| 項目 | 説明 |
|---|---|
| 方針 | セキュア開発・OSS管理・機密管理の方針と、製造者としての責任分担 |
| セキュリティ・OSS要件 | 要件ID (SEC-xxx / OSS-xxx) 、区分、要件、確認方法、備考 |
| コード署名 | 署名の対象、扱い、証跡 |
| 支給品・機密情報の取扱い | 取扱環境、アクセス管理、委託終了時の返却・消去 |
| OSS方針の補足 | ライセンス確認と使用禁止コード |
| 生成AI・参照資料 | 生成AIの利用条件と権利・ライセンスの保証 |

## 9.納品物一覧

| 項目 | 説明 |
|---|---|
| 納品物一覧 | 納品物ID (DLV-01〜DLV-14) 、名称、内容、形式、納品時期、検収対象の有無 |
| 納品方法 | ソースのタグ付け、成果物の登録とハッシュ一覧 |
| 命名規則 | 納品ファイルの命名規則 |
| 納品物ディレクトリ構成 | 納品時のディレクトリ構成 |
| 納品時チェックリスト | 納品前に確認する事項 |

納品物IDは本シートが正本であり、他シートはこれに合わせる。  

## 10.スケジュール

| 開発スケジュール (ガント図) | 工程ごとの期間と、契約締結・納品・検収・リリース・マイルストーンの時期 |
| マイルストーン | MS、日程、内容、判定基準、判定者 |
| 会議予定 | 会議、時期・頻度、参加者、内容、記録 |
| 注意事項 | 休日の扱い、遅延時の報告、日程変更の手順 |

| 項目 | 説明 |
|---|---|

| 役割表 | 役割、所属、主な責務 |
| 会議体 | 会議体、頻度、参加者、内容、記録 |
| 週次進捗報告の内容 | 報告項目、内容、期限・形式 |
| 課題・リスク管理 | 管理方法と対応期限 |
| 変更管理手順 | 仕様・日程を変更する際の手順 |
| 偽装請負の防止 | 指揮命令系統に関する遵守事項 |
| コミュニケーションツール | 用途、手段、管理者 |
| エスカレーション | 解決しない事項や重大問題の報告経路 |
| 管理要件 | 要件ID (MGT-xxx) 、区分、要件、確認方法、備考 |

## 12.検収・契約条件

| 項目 | 説明 |
|---|---|
| 契約形態 (工程別) | 工程、契約形態 (準委任 / 請負) 、期間、主な成果物 |
| 検収手順 | 納品から受入テスト、検収通知、不合格時の再納品までの手順 |
